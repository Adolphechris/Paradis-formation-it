## 🎯 STRATÉGIE PÉDAGOGIQUE GLOBALE

### Principe 1 : Zéro jargon sans analogie
Tout concept technique doit être expliqué par une analogie métier (ex: CPU = chef de projet, RAM = bureau de travail, OS = processus métier).

### Principe 2 : Un concept = une commande = un résultat visible
Pas de théorie abstraite sans exécution concrète. Chaque jour doit produire un livrable visible (script, capture, fichier).

### Principe 3 : Progression en entonnoir
Chaque jour renforce le précédent. Pas de saut de 3 jours sans consolidation.

### Principe 4 : Visibilité permanente du "pourquoi"
Chaque module doit dire : "ceci te sert pour X, Y, Z dans les semestres suivants".

## 📅 ACTION 1 — MODULE DE TRANSITION S0→S1 (7 JOURS)

**Emplacement :** `docs/tome-p0/`  
**Fichiers :** `jour-0p.md` à `jour-0v.md`  
**Durée :** 7 jours × 6h = 42h  
**Position :** Après J0o (examen S0), avant J01 (S1)

### Concept
Le module S0 actuel est excellent pour l'éveil, mais il ne prépare pas à la **rigueur S1**. Les 7 jours de transition vont :
1. Familiariser avec le format S1 (narration + anatomie technique + atelier + diagnostic terrain + portfolio)
2. Introduire les codes compétences BIT
3. Créer des "mini-livrables" portfolio pour préparer aux exigences S1
4. Expliquer la méthodologie "Diagnostic & Réflexes Terrain"
5. Faire le lien entre S0 (concepts) et S1 (mise en œuvre)

### Plan détaillé des 7 jours

| Jour | Titre | Durée | Objectif | Livrable portfolio |
|---|---|---|---|---|
| **J0p** | Format S1 : Narration, Anatomie, Atelier, Diagnostic | 6h | Comprendre la structure d'une journée S1 | Checklist format S1 + capture d'écran |
| **J0q** | Codes compétences BIT : la grille de progression | 6h | Maîtriser les codes BIT (BIT-01 à BIT-12) | Tableau de progression personnel |
| **J0r** | Diagnostic & Réflexes Terrain : la méthode S1 | 6h | Apprendre à dépanner : lecture erreurs, isolation, docs | 3 diagnostics résolus + méthode |
| **J0s** | Portfolio S1 : qu'est-ce qu'un livrable ? | 6h | Comprendre les exigences de preuves S1 | Premier script portfolio `mon_script.sh` |
| **J0t** | Terminal Linux intensif : 50 commandes essentielles | 6h | Maîtriser navigation, fichiers, processus, droits | Cheat sheet 50 commandes |
| **J0u** | Git & GitHub : ton premier dépôt | 6h | Comprendre versionning, commits, branches | Dépôt GitHub `paradis-s0-transition` |
| **J0v** | Examen de transition : S0→S1 validation | 6h | Valider acquis transition (75% seuil) | Badge "Transition S0→S1" |

### Points clés
- **J0p** montre un exemple complet de journée S1 (lecture commentée d'une journée type)
- **J0q** explique la grille BIT et pourquoi elle existe (traçabilité, certification)
- **J0r** transpose J0m (méthodologie S0) en format S1 (diagnostic terrain)
- **J0s** montre des exemples de portfolios S1 (scripts, captures, rapports)
- **J0t** est un bootcamp intensif de commandes Linux — tu as 12h/jour, on peut y aller
- **J0u** introduit Git avec un vrai dépôt, pas de la théorie
- **J0v** est l'examen qui débloque S1-J01

### Critères de réussite
- 75% à l'examen J0v (30/40 QCM)
- Livraison du dépôt GitHub `paradis-s0-transition`

## 🎓 ACTION 2 — MILESTONE J300 "DIPLÔME BACHELOR BIT"

**Emplacement :** Entre S4 (J200) et S5 (J201)  
**Concept :** Un milestone n'est pas un examen de plus. C'est un **rituel de passage** avec 3 composantes :
1. **Épreuve technique** (synthèse S1–S4)
2. **Projet intégrateur** (application réelle)
3. **Cérémonie** (symbolique)

### Structure du milestone J300

| Composante | Durée | Contenu | Livrable |
|---|---|---|---|
| **J300a** | 6h | Épreuve de synthèse Bachelor BIT (50 QCM) | Note ≥ 75% |
| **J300b** | 6h | Projet intégrateur : "Déployer l'infrastructure BCC" | Architecture complète + scripts |
| **J300c** | 6h | Soutenance devant jury (simulé) | Vidéo de présentation |
| **J300d** | 6h | Célébration & passage Master | Badge "Bachelor BIT" + serment |

### J300a — Épreuve de synthèse (50 QCM)
- Couvre S1–S4 : Linux, Windows, Bash, Python, SQL, Git, Réseaux, Sécurité, Docker, Cloud, IaC
- 75% seuil
- Format : questions mélangées, pas de réponses fournies

### J300b — Projet intégrateur
**Sujet :** "Concevoir et déployer l'infrastructure complète de la Banque Centrale du Congo (BCC) — 100 employés"

Livrables :

- Monitoring (Prometheus + Grafana)

### J300c — Soutenance
- 10 minutes de présentation

### J300d — Cérémonie
- Texte du serment d'ingénieur BIT

### Critères de réussite

## 🚨 POINTS D'ATTENTION SPÉCIFIQUES (profil Adolphe)

### 1. Tu n'as aucune base en informatique
- Chaque concept doit être expliqué **du point zéro**
- Pas de raccourci "tu sais déjà ce qu'est un fichier"
- Les analogies doivent être **métier** (ex: fichier = document, dossier = classeur, arborescence = organigramme)

### 2. Tu as 12h/jour disponibles
- Certains jours S1 demandent 6h, tu peux aller à 8–10h en approfondissant
- Les TPs peuvent être étendus (ex: J0t = 50 commandes au lieu de 10)
- Tu peux faire des allers-retours entre jours connexes

### 3. Tu as de l'expérience en gestion de projet ERP
- Exploite ça : le parcours est un **projet** avec jalons, livrables, risques, planning
- Les concepts de governance (S12) te seront plus naturels que la technique pure
- La structuration des modules S0–S1 doit être **aussi claire qu'un cahier des charges**

### 4. Tu es passionné mais risque de frustration
- La technique demande de la **pratique**, pas seulement de la théorie
- Certains concepts (BGP, PQC, Kernel) sont **difficiles** : il faut accepter de ne pas tout comprendre du premier coup
- Les "échecs" (quiz ratés, scripts qui plantent) sont **normaux** et font partie de l'apprentissage
