## 📖 1. Conteneur vs VM : la différence fondamentale

| Critère | Conteneur (Docker) | Machine Virtuelle (Proxmox/KVM) |
|---|---|---|
| **Isolation** | Partagent le noyau de l'hôte | Noyau complètement isolé (hyperviseur) |
| **Légèreté** | Léger (Mo), démarrage en secondes | Lourd (Go), démarrage en minutes |
| **OS** | Même noyau que l'hôte | OS complet invité |
| **Sécurité** | Isolation processuelle (namespaces/cgroups) | Isolation matérielle (hyperviseur) |
| **Cas d'usage** | Dev/test, microservices, CI/CD | Production critique, multi-OS, legacy |
| **Performance** | Native (pas d'émulation) | Légère perte d'overhead hyperviseur |

**Analogies métier** :
- Conteneur = **bureau partagé** : vous partagez le bâtiment (noyau), mais vous avez votre propre espace (namespace).
- VM = **immeuble dédié** : vous avez votre propre bâtiment, complètement isolé.

---

## 📖 2. Quand utiliser un conteneur ? Quand utiliser une VM ?

### Utiliser un conteneur (Docker) quand :
- ✅ Vous avez besoin de vitesse de déploiement (dev/test).
- ✅ Vous déployez des microservices éphémères.
- ✅ Vous faites du CI/CD (pipeline reproductible).
- ✅ L'application est moderne et conçue pour être stateless.

### Utiliser une VM (Proxmox) quand :
- ✅ Vous avez besoin d'isolation complète (production critique).
- ✅ Vous devez faire tourner un OS différent de l'hôte.
- ✅ Vous avez des workloads legacy (Windows Server 2019, applications anciennes).
- ✅ Vous avez des exigences de sécurité maximales (environnement bancaire, financier).

---

## 📖 3. Architecture hybride : le meilleur des deux mondes

Dans une entreprise nord-américaine moderne, les deux coexistent :

```
[Cloud AWS/Azure]
    ↓
[Load Balancer]
    ↓
├── [Conteneurs Docker/K8s] ← Microservices, APIs, CI/CD
├── [VMs Proxmox] ← Serveurs critiques, AD, bases de données
└── [VMs Cloud] ← Environnements de test, PRA
```

**Règle d'or** : Conteneurs pour la vitesse, VMs pour la sécurité critique.

## 🧪 Atelier Pratique : Migrer une app Docker vers VM Proxmox

### Scénario
Vous avez une application web en conteneur Docker (`nginx:alpine`). Vous devez la migrer vers une VM Ubuntu sur Proxmox pour des raisons de sécurité.

### Étape 1 : Conteneur Docker (point de départ)
```bash
# Lancer Nginx en conteneur
docker run -d -p 80:80 --name web-app nginx:alpine

# Vérifier que ça marche
curl http://localhost
```

### Étape 2 : Créer la VM sur Proxmox
```bash
# Sur le serveur Proxmox (via interface web ou CLI)
# Créer une VM Ubuntu 24.04 avec 2 Go RAM, 20 Go disque
# Installer Nginx dans la VM
ssh adolphe@10.0.30.10
sudo apt update
sudo apt install nginx -y
```

### Étape 3 : Configurer le firewall
```bash
# Sur la VM
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
```

### Étape 4 : Tester
```bash
# Depuis votre poste
curl http://10.0.30.10
```

### Livrable
- Script Docker du conteneur original.
- Script de déploiement de la VM.
- Capture d'écran de Nginx fonctionnel sur la VM.

## ❓ Banque de QCM & Test du Jour (5 Questions)

**Q1 : Quelle est la différence principale entre un conteneur et une VM ?**
- A) Le conteneur partage le noyau, la VM a un noyau isolé
- B) La VM est plus légère que le conteneur
- C) Le conteneur est plus lent
- D) Aucune différence

*Réponse : A — Conteneur = partage du noyau, VM = isolation complète.*

**Q2 : Quand préférer une VM à un conteneur ?**
- A) Production critique, isolation maximale, workloads legacy
- B) Dev/test uniquement
- C) Jamais
- D) Pour les applications web seulement

*Réponse : A — VM = isolation complète, production critique, legacy.*

**Q3 : Quand préférer un conteneur à une VM ?**
- A) Dev/test, microservices, CI/CD, déploiement rapide
- B) Production critique seulement
- C) Jamais
- D) Pour les bases de données seulement

*Réponse : A — Conteneur = vitesse, légèreté, éphémère.*

**Q4 : Qu'est-ce qu'un hyperviseur ?**
- A) Le logiciel qui exécute et isole les VMs (ex: KVM, Proxmox)
- B) Un type de conteneur
- C) Un système d'exploitation
- D) Un protocole réseau

*Réponse : A — L'hyperviseur (KVM) est le moteur qui fait tourner les VMs.*

**Q5 : Quelle est la règle d'or pour choisir entre conteneur et VM ?**
- A) Conteneurs pour la vitesse, VMs pour la sécurité critique
- B) Toujours utiliser des conteneurs
- C) Toujours utiliser des VMs
- D) Peu importe

*Réponse : A — Conteneurs = vitesse/agilité, VMs = isolation/ sécurité.*
