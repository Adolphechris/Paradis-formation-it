    JOUR 44 — Simulation finale & remédiation (14h)¶

    Découpage horaire¶

    • Test technique complet en conditions réelles (150 questions, 4h, tous domaines) — 4h
    • Correction + scoring détaillé — 2h
    • Remédiation ciblée sur les points faibles — 5h
    • Revue des projets portfolio + vérification finale — 2h
    • Suivi P1 + préparation J45 — 1h

    1) Test technique final — conditions réelles (4h)¶

    Objectifs d'apprentissage¶

    • Valider les acquis PARADIS dans une simulation finale.
    • Identifier les points faibles finaux et documenter la remédiation nécessaire.
    • Vérifier l'état de préparation du portfolio et des documents de candidature.

    Contenu pédagogique¶

    • Appliquer une épreuve complète de 150 questions sur tous les domaines.
    • Analyser les résultats pour distinguer force et faiblesse.
    • Préparer une clôture professionnelle du programme.

    Exercices¶

    • Réaliser le test technique complet de 150 questions.
    • Documenter les réponses et les zones d'amélioration.

    Consignes strictes (simule le jour J)¶

    • 150 questions sur tous les domaines PARADIS. 4h chronométrées, pas de pause, pas de documentation.
    • Format : 60% QCM, 25% ouvertes courtes, 15% cas pratiques.
    • Objectif : score >= 80% (120/150).

    2) Correction + scoring détaillé (2h)¶

    Grille de scoring¶

    • QCM : 1 point. Question ouverte : 1 point (mots-clés + justesse). Cas pratique : 1 point.

    Analyse par domaine¶

    Calculer le % par domaine. Identifier les forces (> 85%) et faiblesses (< 70%).

    Interprétation¶

    • >= 120/150 (80%) : Niveau Professionnel du numérique CONFIRMÉ. Prêt pour les entretiens.
    • 100-119/150 (67-79%) : Bon niveau, remédiation ciblée.
    • < 100/150 (< 67%) : Révision approfondie nécessaire.

    3) Remédiation ciblée (5h)¶

    Méthode¶

    Pour chaque domaine < 70% : relecture fiche synthèse (30 min) → 15 questions ciblées (1h) → mini-exercice pratique (1h).

    Ressources¶

    Revoir les fiches de révision J36-J38 et les journées correspondantes du programme.

    4) Revue des projets portfolio (2h)¶

    Checklist finale¶

    • Les 4 projets principaux ont un README complet
    • Les liens GitHub et démo fonctionnent
    • Le portfolio en ligne est accessible
    • Le CV est à jour
    • Le dossier de candidature est complet

    5) Suivi P1 + préparation J45 (1h)¶

    Préparer le pitch final, revoir l'argumentaire UNISA, anticiper les questions d'entretien pour J45.

    Validation qualité J44¶

    Livrables¶

    1. Test 150 questions scoré (>= 80% = 120/150).
    2. Rapport d'analyse par domaine.
    3. Remédiation documentée.
    4. Portfolio vérifié et fonctionnel.

    J44 — Test technique final¶

    1. B — TCP est fiable (handshake 3 volets, accusés de réception, retransmission) ; UDP est rapide mais sans garantie de livraison
    2. B — Zéro Trust = « Never trust, always verify ». Chaque requête est authentifiée et autorisée, même à l'intérieur du réseau
    3. B — Le modèle de responsabilité partagée signifie que le fournisseur cloud sécurise l'infrastructure (hardware, datacenter) et tu sécurises tes données et configurations
    4. Ouverte : « 5 étapes : (1) Vérifier la connectivité réseau, (2) Vérifier que le service est actif (systemctl), (3) Consulter les logs (journalctl), (4) Tester l'application, (5) Documenter et résoudre. »
    5. Ouverte : « L'incident est l'événement non planifié (le site est down). Le problème est la cause racine inconnue du ou plusieurs incidents (ex : fuite mémoire). »
    6. B — JWT (JSON Web Token) contient un header (type d'algorithme), un payload (claims/données), une signature (vérification d'intégrité). Le client stocke le token et l'envoie dans chaque requête Authorization header : Bearer <token>
    7. Ouverte — Tu peux utiliser chunks dans pandas (pd.read_csv(chunk_size=100000)) pour lire par morceaux, ou traiter ligne par ligne en Bash, ou utiliser des outils comme awk pour un filtrage rapide sans tout charger en mémoire.
    8. B — Zero Trust repose sur 5 principes : (1) Vérifier explicitement chaque accès, (2) Moindre privilège, (3) Supposer la compromission, (4) Segmenter les réseaux, (5) Collecter toutes les données pour analyse. Le modèle traditionnel « périmètre fort » suppose que tout ce qui est derrière le pare-feu est sûr — ce qui est faux si un attaquant y pénètre.
