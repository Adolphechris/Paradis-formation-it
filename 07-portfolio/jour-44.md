### J44 — Test technique final

1. **B** — TCP est fiable (handshake 3 volets, accusés de réception, retransmission) ; UDP est rapide mais sans garantie de livraison
2. **B** — Zéro Trust = « Never trust, always verify ». Chaque requête est authentifiée et autorisée, même à l'intérieur du réseau
3. **B** — Le modèle de responsabilité partagée signifie que le fournisseur cloud sécurise l'infrastructure (hardware, datacenter) et tu sécurises tes données et configurations
4. **Ouverte** : « 5 étapes : (1) Vérifier la connectivité réseau, (2) Vérifier que le service est actif (systemctl), (3) Consulter les logs (journalctl), (4) Tester l'application, (5) Documenter et résoudre. »
5. **Ouverte** : « L'incident est l'événement non planifié (le site est down). Le problème est la cause racine inconnue du ou plusieurs incidents (ex : fuite mémoire). »
6. **B** — JWT (JSON Web Token) contient un header (type d'algorithme), un payload (claims/données), une signature (vérification d'intégrité). Le client stocke le token et l'envoie dans chaque requête Authorization header : `Bearer <token>`
7. **Ouverte** — Tu peux utiliser `chunks` dans pandas (`pd.read_csv(chunk_size=100000)`) pour lire par morceaux, ou traiter ligne par ligne en Bash, ou utiliser des outils comme `awk` pour un filtrage rapide sans tout charger en mémoire.
8. **B** — Zero Trust repose sur 5 principes : (1) Vérifier explicitement chaque accès, (2) Moindre privilège, (3) Supposer la compromission, (4) Segmenter les réseaux, (5) Collecter toutes les données pour analyse. Le modèle traditionnel « périmètre fort » suppose que tout ce qui est derrière le pare-feu est sûr — ce qui est faux si un attaquant y pénètre.
